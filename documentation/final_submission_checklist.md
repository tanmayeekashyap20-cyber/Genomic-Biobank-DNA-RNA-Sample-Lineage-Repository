# Final Project Submission Checklist

## 1. Project Source Code

- [ ] Frontend source code is included.
- [ ] Backend API routes are included.
- [ ] Database connection modules are included.
- [ ] Authentication and authorization code is included.
- [ ] Required configuration files are included.
- [ ] Unnecessary generated files and temporary files are excluded.

## 2. Database Deliverables

- [ ] PostgreSQL schema scripts are included.
- [ ] Sample data scripts are included, where appropriate.
- [ ] SQL query scripts are included.
- [ ] Advanced database feature scripts are included.
- [ ] Entity-Relationship diagram is included.
- [ ] MongoDB lineage event structure is documented.
- [ ] Database relationships and constraints are documented.

## 3. Application Features

- [ ] Donor management functionality is documented.
- [ ] Consent management functionality is documented.
- [ ] Sample management functionality is documented.
- [ ] Sample processing functionality is documented.
- [ ] Sample lineage functionality is documented.
- [ ] Storage management functionality is documented.
- [ ] Experiment management functionality is documented.
- [ ] Sequencing result functionality is documented.
- [ ] Authentication and role-based access are documented.

Confirm that each feature is implemented before presenting it as a completed feature.

## 4. Documentation Deliverables

- [ ] Project overview
- [ ] Backend architecture
- [ ] Database design decisions
- [ ] Database relationships
- [ ] Data dictionary
- [ ] MongoDB lineage documentation
- [ ] Authentication and authorization documentation
- [ ] API reference
- [ ] Backend setup guide
- [ ] Installation and configuration guide
- [ ] Functional and non-functional requirements
- [ ] Project glossary
- [ ] Development workflow
- [ ] User guide
- [ ] Limitations and future enhancements
- [ ] Team contributions

## 5. Screenshots and Diagrams

- [ ] Database ER diagram
- [ ] Application dashboard
- [ ] Login interface
- [ ] Donor and sample management screens
- [ ] Sample lineage visualization
- [ ] Database-related screenshots
- [ ] Other relevant application screens

Use screenshots from the actual project implementation.

## 6. Security and Configuration

- [ ] No passwords or database credentials are committed.
- [ ] Local environment files are excluded from version control.
- [ ] Authentication secrets are not exposed.
- [ ] Demo data is clearly distinguished from real records.
- [ ] Sensitive donor information is not included in public screenshots.

## 7. Team and Repository

- [ ] Team member responsibilities are documented.
- [ ] GitHub repository contains the intended project files.
- [ ] Relevant feature branches are preserved.
- [ ] The final integration branch is identified.
- [ ] README instructions match the actual project setup.
- [ ] Required technologies are consistent with the project specification.

## 8. Final Review

- [ ] Documentation matches the actual implementation.
- [ ] Incomplete features are clearly identified.
- [ ] Database and application architecture are explained.
- [ ] Known limitations are documented.
- [ ] Final presentation and project report are prepared.
- [ ] Testing and final verification are completed before submission.

## 9. Submission Readiness

The project should be considered ready for submission only after the implementation, documentation, database deliverables, and required verification activities have been reviewed.

This checklist is a planning document. Checking an item should indicate that the corresponding deliverable has actually been completed.
